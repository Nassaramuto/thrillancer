# 10–20-person proof session

## Before event
Record build commit, network configuration, server location, device/browser matrix and devnet label. Test guest access, wallet login, profile, chat, race, repair, Home, reconnect and outside camp with two real sessions. Have demo SOL available via a permitted devnet faucet; wallets are optional. Never ask participants for seed phrases. Ensure receipt recipient is disclosed. Prepare backup guest path if wallet/RPC fails.

## 45-minute session
0–5: Enter and identify one other real person.
5–10: Chat, inspect profile, teleport to venue.
10–20: Race and return; join repair and return.
20–25: Optional wallet authentication and devnet payment confirmation/rejection.
25–35: Visit outsider camp; builder publishes an update through documented route.
35–45: Gather feedback and announce next event.

## Observe
Arrival-to-first-activity time, independent task completion, room transition success, reconnect, duplicate results, frame rate, latency, browser/server errors. Keep activity records tied to internal user IDs and collect only necessary wallet data. Use consented logging; do not expose raw chat histories by default.

## Ask
What would you return for? What was enjoyable? What did 3D improve? Where did you get lost? Would you attend another hosted event? Builder: what required maintainer help?

## Decision
Technical pass: real multiplayer, verified wallet login/payment, two completed journeys and outsider publication work reliably. Product signal: participants voluntarily join a second activity and return for a later event. Attendance at a recruited session alone is not retention. No claim of product-market fit from one event.
